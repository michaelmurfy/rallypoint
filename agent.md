# Agent guide

Rallypoint: cross-platform (macOS, Windows, Linux) launcher and multiplayer stack for C&C Generals / Zero Hour. User-facing docs are in `README.md`; this file is for contributors and AI agents.

## Layout
- `engine/` - git submodule: https://github.com/dvcdsys/GeneralsGameCode-macOS (fork of TheSuperHackers/GeneralsGameCode, itself from EA's GPL release). Don't edit in place; engine changes are `patches/*.patch`.
- `patches/` - `sh patches/apply.sh` applies them to `engine/` (idempotent). Regenerate: edit the engine tree, `git -C engine add -N <new files> && git -C engine diff -- <paths> > patches/NNNN-name.patch`, then `git -C engine reset` + checkout, and re-apply. `0001-widescreen.patch` = hor+ camera, uniform/centred 2D UI, terrain draw window on all platforms (`GEN_STRETCH=1` restores retail). `0002-relay-transport.patch` = the `UDP` class tunnels through the agent when `GEN_RELAY`/`GEN_RELAY_VIP` are set and drops datagrams not from the agent; `LANAPI::SetLocalIP` uses the virtual IP. Wire code is `RelayWire.h`. `0003-macos-args-resolution-fullscreen.patch` = macOS only: `main()` forwards argv (the port dropped it, so `-xres/-yres/-fullscreen/-mod` were silently ignored), the Metal display-mode list is built dynamically (common sizes that fit the screen + the native size + `GEN_EXTRA_RES`, which the launcher always sets), and the Metal layer honours `windowed=0` with native fullscreen (`MetalContext_SetWindowed`). `0004-macos-hidpi-font-scale-and-trackpad-zoom.patch` = font size follows the uniform UI scale (min of width/height scale, was width only, so text was huge on wide/Retina screens; `GEN_STRETCH=1` keeps retail) and trackpad/Magic Mouse scroll is scaled and clamped (it wrapped the signed 16-bit wheel value, so zoom jumped or flipped). `0005-base-game-path-all-platforms.patch` = `GEN_GENERALS_PATH` (set by the launcher) now works on Windows too; Steam does not write the EA registry key, so Zero Hour started without the base game's data and died with "You have encountered a serious error". `0006-windows-dpi-window-frame.patch` = the window frame is sized for the system DPI (the manifest already makes the engine per-monitor DPI aware). `0007-mod-folder-loads-gib.patch` = the `-mod` folder also loads `*.gib` (Shockwave ships some archives under that name), before `*.big`. `0008-max-camera-height-env.patch` = `GEN_MAX_CAMERA_HEIGHT` (300-1500) overrides `MaxCameraHeight` after GameData.ini loads; the launcher sets it from Settings > Graphics (default 510, from github.com/trailblazingfive/cnc-generals-graphics-fix, whose `Options.ini` key of that name is ignored by the engine). `launcher/core/src/graphics.rs` also merges that repo's quality options into `Options.ini` on request, keeping a backup. `0009-network-diagnostic-log.patch` = always-on `[net]` lines on stderr (relay config, bind and update failures); the launcher writes engine output to `<app data>/GeneralsZH/engine.log` and Settings > Troubleshooting shows its tail. `0010-relay-locks-local-ip.patch` = in relay mode `LANAPI` never has any address but the virtual IP (constructor and `init()`, not only `SetLocalIP`). `launch::relay_for_launch` refuses to start the game while the relay is connecting or rejected. `0011-lan-wire-format-and-winsock-version.patch` = the macOS WSAStartup shim now sets `wVersion` (it was left uninitialised, so `Transport::init` bailed before creating the socket: the "Failed trying to communicate with the network" box) and LAN lobby packets use a 16-bit-character wire layout (`LANMessageT<uint16_t>`, converted in `LANAPI::sendMessage`/`update`; the native struct was 536 bytes against a 476 byte packet limit on macOS, so lobby packets were rejected, and it matches what Windows sends). `launcher/core/examples/agent_cli.rs` joins a room like the launcher so the engine's UDP code can be tried against a real server (see the PR for the harness). These need a real macOS test. All build in CI on macOS and Windows; none has been played in a real game.
- `tests/` - `sh tests/run.sh` applies patches and runs the standalone engine-math tests (plain `c++`, no engine build); `relaywire_test` checks the same golden bytes as the Rust protocol tests.
- `launcher/core/` - GUI-free Rust crate, all logic and tests: `steam.rs` (find installs by `.big` files), `assets.rs` (Steam download with DepotDownloader: native on every OS, so no Rosetta; pinned version + SHA-256 per platform, checksums from `.github/workflows/tool-checksums.yml`; password goes to its stdin when it prompts, never argv; prompts have no trailing newline and a "wrong code" notice can arrive before or after the next prompt because stdout/stderr are separate pipes; `-remember-password` makes later runs prompt-free; phone approval (push notification) is the default sign-in, so `-no-mobile` is only added when the user taps "Enter a code instead" (the interrupted run is restarted, reusing the in-memory password), and a quiet 6 s of signing in also shows the phone hint because the tool's exact wording is unverified; tested against a fake tool), `extract.rs` (safe unzip/7z/rar/tar/installer-exe via system tools: lists and checks entries for `..`/absolute paths before extracting, rejects symlinks), `maps.rs` (map packs: download a zip with curl, safe-extract, copy only the map folders (a folder holding a `.map`) into `<Documents>/Command and Conquer Generals Zero Hour Data/Maps`; catalog `mods/mappacks.json` lists GenTool's `Maps_*_ZH.zip` files, URLs verified with HEAD requests), `update.rs` (GitHub releases updater: semver precedence incl. prereleases, per-OS installer pick, SHA256SUMS check, only this repo's download URLs; CI stamps the tag into the binary with `RALLYPOINT_VERSION`), `proc.rs` (`quiet()`: CREATE_NO_WINDOW for every helper process on Windows; the launcher itself uses the GUI subsystem in release builds), `mods.rs` (catalog with `addon_for` add-ons: the engine loads one mod folder, so `compose()` hard-links base + add-on into `Mods/.run-<addon>` at launch; catalog, install from archive/folder/exe into `Mods/<folder>`, flatten wrapper dirs, require `.big` files, remove, Downloads-folder watcher), `engine.rs`, `launch.rs`, `config.rs` (`<app data>/GeneralsZH/config.json`, 0600), `agent.rs` (tunnel agent).
- `launcher/src-tauri/` - thin Tauri 2 shell exposing core as commands (mod installs are `async` + `spawn_blocking` so the window doesn't freeze). `launcher/ui/` is plain HTML/CSS/JS built from small DOM components in `app.js` (`h()` helper, no `innerHTML`, no inline styles because of the CSP): sidebar pages Play/Mods/Online/Settings plus the first-run wizard (`config.setup_done`). `scripts/ui-preview/` renders it in a normal browser with a mocked backend (`python3 -m http.server`, open `scripts/ui-preview/index.html#fresh`); check changes there, including `null` text from `replaceChildren` (use `fill()`).
- `mods/mods.json` - mod manifest. A mod is a folder under `<app data>/GeneralsZH/Mods/` loaded with `-mod`.
- `shared/` (`generals-proto`) - UDP wire protocol and `room_verifier`. `server/` (`rallypoint-server`, Linux) - `Server` state machine in `lib.rs` (no sockets or clocks; all tests there), `geo.rs` (country filter), `main.rs` (env config, CLI, UDP loop).
- `Makefile`, `.env.example`, `docker-compose.yml`, `server/Dockerfile` - running the server. CI smoke-tests the container with `launcher/core/examples/agent_cli.rs` (a full encrypted sign-up and join using the real agent).
- `.github/workflows/ci.yml` - fast tests only, on push/PR. `release.yml` - engine + launcher bundles + server image, only on `v*` tags or manual run (manual never publishes).

## Commands
- `make test` (= `cargo test -p generals-core -p generals-proto -p generals-server` + `sh tests/run.sh`) before every commit.
- `cargo check -p generals-launcher` - needs webkit2gtk dev packages on Linux.
- `cd launcher/src-tauri && cargo tauri build` - needs the engine copied into `launcher/src-tauri/engine/`.
- Release: `make release VERSION=0.1.0-alpha.1` (tag must match `tauri.conf.json` version's numeric core). Dry run: Actions > Release > Run workflow.
- Clone with `git clone --recurse-submodules --depth 1`; the engine repo is large.
- No cmake/Docker is assumed locally; engine builds are verified through the release workflow.

## Server design
- Encryption (`shared/src/secure.rs`, the `snow` crate, Noise `NK` over X25519/ChaCha20-Poly1305/SHA-256; no hand-rolled crypto): the server has a long-term key pair (`serials.key` next to the serials, 0600; `rallypoint-server key` prints the fingerprint). A client learns it once with `KeyRequest`/`KeyReply` (padded so the reply is smaller than the request), saves it per server in the launcher config (`server_keys`, trust on first use) and from then on only that server can complete a join; a different one is reported as `ServerKeyChanged` and refused until the player chooses `relay_forget_key`. Handshake: `Hs1{cookie, msg1}` where msg1 is the client's `Register` or `Hello{serial, room, verifier}` encrypted to the server key (an unknown cookie only gets a small `Challenge`: no key exchange is spent on spoofed senders), answered by `Hs2{msg2}` carrying `Issued`/`Welcome{vip}`/`Reject`. After that every datagram is `Transport{counter || AEAD(packet)}` with per-direction keys and a 64-packet replay window; forged, replayed or unknown-session datagrams get no reply. A retransmitted msg1 is answered from a cache (same reply, no second session). `Wire` is the outer layer, `Packet` the content (also what the engine speaks to the local agent, unchanged).
- Serials are identities issued automatically and kept out of the UI. The challenge cookie (HMAC-like SHA-256 over a server secret + source IP + minute) stops spoofed sign-ups; the Challenge is no bigger than the request (no reflection). 5 sign-ups per IP per hour. `GENERALS_REGISTRATION=closed` makes the server admin-issue only (`rallypoint-server issue <label>`).
- Rooms: created by the first `Hello` for a name with its `verifier` (iterated SHA-256 of room+password, so the password never travels or is stored), removed when empty (explicit `Leave`, timeout 30 s, serial revoked). Max 256 rooms x 8 players; 10 wrong passwords per IP per 10 minutes. Broadcast/unicast never cross rooms; each room has its own `10.77.0.x` space.
- Country limit: `ALLOWED_COUNTRIES` + zone files in `GEO_DIR` (`make geo` downloads ipdeny.com aggregated lists). Fails closed (listed country without a file allows nobody); private ranges pass unless `ALLOW_PRIVATE=false`. Blocked sources get no reply.
- Game only: the relay carries nothing but the engine's own datagrams. Logical ports are limited to 8086 (lobby; broadcast is lobby-only) and 8088 (game), payload ≤ 1100 bytes, and `generals_proto::is_game_packet` checks the engine's obfuscation, CRC and magic 0xF00D (verified against packets built by the engine's own `Transport` code; `game_packet` builds one for tests). The agent applies the same filter in both directions and ignores `Bind` for other ports.
- Abuse limits: per-session 600 packets and 400 kB per second (dropped, not echoed); per address (IPv6 by /64) 16 sessions, 20 unknown-serial guesses and 10 wrong passwords per 10 minutes, 5 sign-ups an hour; 300 sign-ups an hour server-wide. Housekeeping (expiry, serial file reload) runs once a second in `main.rs`, never per datagram.
- Diagnostics: a signed `StatsRequest` is answered with `Stats` (counts only: rooms, players, players in your room, load %, packets/s and kbit/s of the last second, uptime, version; never other rooms' names). The agent pings every 2 s, keeps 30 results for latency, jitter and loss (`Health`), and the Online page shows them (`relay_diagnostics`).
- Limits: the first visit to a server trusts whoever answers `KeyRequest` (like SSH); pinned afterwards. msg1's payload (serial, room proof) has no forward secrecy if the server key leaks later (Noise NK); everything after has. The agent's loopback socket trusts any local process (same-user threat model), but only game packets pass it.

## Rules
- **Pull requests only.** Never push to `main`. Branch (`feat/…`, `fix/…`, `docs/…`), push the branch, open a PR with `gh pr create`, let CI run, and merge after review. Release tags are the one thing pushed directly, and only from a merged `main` (`make release VERSION=…`).
- Licensing: launcher/server/shared/scripts/docs are MIT (`LICENSE`). Anything derived from the engine (`patches/`, `RelayWire.h`, other engine edits) is GPL-3.0 + EA terms. Never copy engine code into the MIT parts, and keep the launcher talking to the engine only as a separate process.
- Put logic in `launcher/core` or `server` lib with a test; keep the Tauri shell and UI thin.
- Detect games by `.big` files (`INIZH.big` = Zero Hour, `INI.big` = Generals). Steam app IDs (Generals 2229870, Zero Hour 2732960) are used only by the steamcmd download.
- Never redistribute EA assets, Miles or Bink. The user's own Steam copy supplies game data. Never store or log the Steam password; it only goes into the short-lived 0600 sign-in script (never argv), and logs are scrubbed of it.
- Mod catalog entries need verified official URLs (ModDB blocks automated fetches with 403, so open the page in a browser to check); never invent one, and never scrape direct download links: the launcher opens the official page and watches Downloads instead.
- UI: no `innerHTML` with backend data (folder names are attacker-controlled).
- Server loop must never die on I/O errors (no `?` inside `run`'s loop).
- No new dependencies when std or serde does it (sha2 is the exception: don't hand-roll crypto).

## Roadmap
1. Verify in a real game: widescreen/HiDPI (0001), two-machine play through the relay (0002), Steam download with a real account, Windows engine data lookup (cwd vs registry).
2. Linux engine; more catalog mods (needs verified pages); loose-file mods (no `.big`).
   (was 2) GeneralsX (https://github.com/fbraz3/GeneralsX) already targets Linux x86_64 (DXVK/Vulkan, SDL3, OpenAL) from the same TheSuperHackers base; the likely route is basing the Linux build on it rather than porting our own renderer. It publishes no discrete fix list, so cherry-picking means reading its commit history for the specific area (macOS/net/rendering fixes) and porting by hand.
3. Determinism (macOS arm64 vs Windows x86 desync): `-ffp-contract=off`, deterministic trig, RNG audit; headless engine on the server as a per-frame CRC referee.
4. Gameplay features, all engine work in a lockstep game, none started:
   - Save/load multiplayer: needs the save to be written identically on every client and a "load" handshake that restores all clients to the same frame (the game's save format is not network-aware).
   - Controlling allied units: command validation (`Player`/`Object` ownership checks in command processing) needs an "allowed controller" relation that is identical on every client; AI-owned allies and shared vision/economy rules need decisions.
   - Co-op / shared player: several humans issuing commands for one `Player` slot; commands from different clients for the same player must be ordered deterministically (the net layer already orders commands per frame), and the lobby needs a shared slot concept. Related to the item above.
5. Mod downloads inside the launcher; the relay as a public server list.
