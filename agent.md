# Agent guide

Rallypoint: cross-platform (macOS, Windows, Linux) launcher and multiplayer stack for C&C Generals / Zero Hour. User-facing docs are in `README.md`; this file is for contributors and AI agents.

## Layout
- `engine/` - git submodule: https://github.com/dvcdsys/GeneralsGameCode-macOS (fork of TheSuperHackers/GeneralsGameCode, itself from EA's GPL release). Don't edit in place; engine changes are `patches/*.patch`.
- `patches/` - `sh patches/apply.sh` applies them to `engine/` (idempotent). Regenerate: edit the engine tree, `git -C engine add -N <new files> && git -C engine diff -- <paths> > patches/NNNN-name.patch`, then `git -C engine reset` + checkout, and re-apply. `0001-widescreen.patch` = hor+ camera, uniform/centred 2D UI, terrain draw window on all platforms (`GEN_STRETCH=1` restores retail). `0002-relay-transport.patch` = the `UDP` class tunnels through the agent when `GEN_RELAY`/`GEN_RELAY_VIP` are set and drops datagrams not from the agent; `LANAPI::SetLocalIP` uses the virtual IP. Wire code is `RelayWire.h`. `0003-macos-args-resolution-fullscreen.patch` = macOS only: `main()` forwards argv (the port dropped it, so `-xres/-yres/-fullscreen/-mod` were silently ignored), the Metal display-mode list is built dynamically (common sizes that fit the screen + the native size + `GEN_EXTRA_RES`, which the launcher always sets), and the Metal layer honours `windowed=0` with native fullscreen (`MetalContext_SetWindowed`). `0004-macos-hidpi-font-scale-and-trackpad-zoom.patch` = font size follows the uniform UI scale (min of width/height scale, was width only, so text was huge on wide/Retina screens; `GEN_STRETCH=1` keeps retail) and trackpad/Magic Mouse scroll is scaled and clamped (it wrapped the signed 16-bit wheel value, so zoom jumped or flipped). `0005-base-game-path-all-platforms.patch` = `GEN_GENERALS_PATH` (set by the launcher) now works on Windows too; Steam does not write the EA registry key, so Zero Hour started without the base game's data and died with "You have encountered a serious error". `0006-windows-dpi-window-frame.patch` = the window frame is sized for the system DPI (the manifest already makes the engine per-monitor DPI aware). `0007-mod-folder-loads-gib.patch` = the `-mod` folder also loads `*.gib` (Shockwave ships some archives under that name), before `*.big`. `0008-max-camera-height-env.patch` = `GEN_MAX_CAMERA_HEIGHT` (300-1500) overrides `MaxCameraHeight` after GameData.ini loads; the launcher sets it from Settings > Graphics (default 510, from github.com/trailblazingfive/cnc-generals-graphics-fix, whose `Options.ini` key of that name is ignored by the engine). `launcher/core/src/graphics.rs` also merges that repo's quality options into `Options.ini` on request, keeping a backup. `0008-zh-path-and-camera.patch` = if `INIZH.big` is not in the working directory, load `*.big` from `GEN_ZH_PATH`. The check is a local file probe: asking `TheFileSystem` records a miss for `Weather.ini`, and the real load later trusts that instead of the archive (`INI_CANT_OPEN_FILE` during startup). Weather.ini is ZH-only. Camera height and pitch stay opt-in (`GEN_MAX_CAMERA_HEIGHT` / `GEN_CAMERA_PITCH`). 0009-network-diagnostic-log.patch` = always-on `[net]` lines on stderr (relay config, bind and update failures); the launcher writes engine output to `<app data>/GeneralsZH/engine.log` and Settings > Troubleshooting shows its tail. `0010-relay-locks-local-ip.patch` = in relay mode `LANAPI` never has any address but the virtual IP (constructor and `init()`, not only `SetLocalIP`). `launch::relay_for_launch` refuses to start the game while the relay is connecting or rejected. `0011-lan-wire-format-and-winsock-version.patch` = the macOS WSAStartup shim now sets `wVersion` (it was left uninitialised, so `Transport::init` bailed before creating the socket: the "Failed trying to communicate with the network" box) and LAN lobby packets use a 16-bit-character wire layout (`LANMessageT<uint16_t>`, converted in `LANAPI::sendMessage`/`update`; the native struct was 536 bytes against a 476 byte packet limit on macOS, so lobby packets were rejected, and it matches what Windows sends). `launcher/core/examples/agent_cli.rs` joins a room like the launcher so the engine's UDP code can be tried against a real server (see the PR for the harness). `0012-controlbar-scheme-uniform-scale.patch` = the control bar scheme (frame art, options/worker/general/power/money/chat buttons) and `ControlBarResizer` were stretched across the display (display / scheme res) while patch 0001 puts the windows in a centred uniform 4:3 region, so on ultrawide the art and icons were stretched and misplaced; they now map into the same region (`WideScreen::schemeScale`; `GEN_STRETCH=1` restores retail). `0013-relay-only-address.patch` = in relay mode `IPEnumeration` lists only the virtual address (10.77.0.x), so the Options IP box, the LAN lobby and Direct Connect never show or pick the machine's real adapters; offline, a virtual address that was saved into Options.ini while online is ignored. `0014-windows-game-folder-working-directory.patch` = Windows only: `WinMain` changes to `GEN_ZH_PATH` instead of the executable's folder. Rallypoint keeps the engine outside the game folder, and loose files (`Data\Cursors\*.ani`, `Data\Movies`, `Data\Scripts`) are opened by relative path, so every cursor failed to load and the mouse was invisible. `0015-honour-win-and-fullscreen-at-engine-init.patch` = `-win`/`-fullscreen` are read in the engine-init command-line pass as well as the startup pass; on macOS the startup pass saw an empty command line (`Command-line args:` printed nothing the first time) so the game always opened full screen even with Fullscreen off. `0016-clamp-oversized-ini-numbers.patch` = numbers bigger than the field can hold, such as Shockwave's `SpawnReplaceDelay = 9999999999999999999`, clamp to the field's limit instead of rejecting the file (`INI_INVALID_DATA` during startup). `0017-deterministic-simulation.patch` = multiplayer between macOS arm64 and Windows x86 went out of sync at frame 100 (the first CRC check). Changes: `WWLib/detmath.h` (sin/cos/tan/asin/acos/atan/atan2/exp/log/pow from +,-,*,/,sqrt only; every direct libm call in GameLogic, Common and WWMath now uses it; `tests/detmath_test.cpp` checks accuracy and a golden bit hash that CI also checks on x86), `-ffp-contract=off` (macOS) and `/fp:precise` (MSVC) so no a*b+c is fused, `std::stable_sort` in `PartitionSolver`, the executable CRC is now a platform-independent simulation id (`kRallypointSimulationId` in `GlobalData::generateExeCRC`: raise it whenever a change alters how the game plays out) and the Zero Hour LAN join check for exe and INI CRC is switched on (it was disabled upstream), so different simulations or game data are refused at the lobby. Still suspected if games diverge: hash-map iteration order and uninitialised memory; use Settings > Multiplayer sync logs (`-SaveDebugCRCPerFrame`, compared by `launcher/core/src/syncdiff.rs`) to find the first differing frame and line. `0018-relay-sync-quorum.patch` = the relay as referee of desyncs: each engine reports its own simulation checksum (`MSG_LOGIC_CRC` for the local player, `RelayWire_ReportCrc` -> `Packet::Crc` through the agent to the relay); the relay waits until every player in the room has reported a frame and compares them: equal says nothing, different sends `Packet::Desync` to the whole room. The host (slot 0, flagged in `Packet::Crc`) is the master: when exactly one player claims to be the host, everyone whose checksum differs from the host's is marked `odd` and the verdict is `certain` (two hosts cancel out); with no host report a strict majority decides, and with two players or a tie nobody can say who is right, the agent forwards it to the engine, which names the players in an in-game message (`GameLogic::update` -> `reportRelayDesync`), and to the launcher (Online tab, Sync check). At most 3 verdicts per room; the relay holds the last 16 frames per room. Not yet: acting on the verdict, i.e. bringing the odd client back in step with the host (the host would have to save its state mid-game, the relay stream it, and the client load it at the same frame; the engine's save format is not network-aware, see the roadmap), or removing the odd player. `0019-mod-splash-bitmap.patch` = the loading picture is `Install_Final.bmp` from the game folder, so a mod still showed Zero Hour; the launcher sets `GEN_SPLASH` to the mod's bitmap (`Install_Final.bmp`, or Shockwave's `Install_Final_shw.bmp`) when that file is in the mod folder. `0020-sync-log-in-release-builds.patch` = `-SaveDebugCRCPerFrame` and the other CRC debug flags only exist when `DEBUG_CRC` is compiled, which upstream ties to `DEBUG_LOGGING` (debug builds), so in our release builds they were silently ignored and Settings > Multiplayer sync logs wrote nothing. `DEBUG_CRC` is now always on (logging still off until a flag asks; the `DUMP*` macros test the flag before building their string arguments); the two things it also changed upstream stay as before: `NET_CRC_INTERVAL` 100 and no `DeepCRCSanityCheck`. `0021-sync-log-needs-debug-crc-cmake.patch` = 0020 alone was not enough: the fork's `cmake/config-debug.cmake` defined `NO_DEBUG_CRC` (option `RTS_DISABLE_DEBUG_CRC`, ON) in every build, so the code was still compiled out; it is now OFF and the `NET_CRC_INTERVAL`/`DeepCRCSanityCheck` bits are gated on `RTS_DEBUG` (the macOS build has `DEBUG_LOGGING` on, which would otherwise have enabled both). Sync logs also pass `-NetCRCInterval 10` and `-ReplayCRCInterval 10`, since the state is only written when a checksum is taken, and `-LogObjectCRCs` so the file names the object that diverged; the launcher creates the folder first. `0022-sync-log-to-stderr.patch` = the relay's desync note was `DEBUG_LOG` only, and the Windows release build does not define `DEBUG_LOGGING` (the macOS preset does), so `engine.log` never recorded the frame or the checksums; it now prints `[sync]` on stderr and flushes the frame file. The Windows engine job uses the same logging switches as the macOS preset (`RTS_DEBUG_LOGGING` on, crashing/stacktrace/profile off) so the two builds are the same configuration. `0023-sync-log-filename-crash.patch` = the first sync-log line crashed the game at start on macOS (`getFname` did `reverseFind('\\') + 1`, which is `(char *)1` when `__FILE__` has no backslash); it now cuts at either separator. `0024-portable-trig-and-inv-sqrt.patch` = the first real sync-log comparison (Windows host, macOS client) showed the games differing at frame 0: the transform of every rotated object (command centres, bunkers, trees). Cause: `WWMath::Sin`/`Cos`/`Inv_Sqrt` had x87 `fsin`/`fcos` and an approximate inverse square root under `_MSC_VER && _M_IX86`, so Windows never used `DetMath`. Those three now use the portable versions everywhere (`Sqrt` and `Float_To_Long` are left: same result, and render-only), and `kRallypointSimulationId` is 3. In the logs the macOS `m_objectUpgradesCompleted: I64X` is a `%I64X` format that macOS prints literally (log noise only); `syncdiff` already ignores CRLF. `0025-sync-log-transform-detail.patch` = beta.5 logs (Windows host, macOS client) still differed at frame 0 in the transform of terrain-aligned objects (command centres, derricks, fences, wall pieces) after 0024, with only the transform CRC logged; this adds `DUMPREAL`/`DUMPCOORD3D` lines (angle, terrain normal, the x and y axes, terrain height) in `makeAlignToNormalMatrix`/`alignOnTerrain` so the next comparison names the input that differs, and logs `m_objectUpgradesCompleted` with `toHexString()` instead of passing a class through `%I64X`. `0026-borderless-fullscreen-keeps-its-frame-off.patch` = Windows fullscreen is a borderless `WS_POPUP`, but it also had `WS_SYSMENU`, so moving the window to another virtual desktop or monitor made Windows put a border back; the fullscreen window no longer asks for a system menu, `WM_NCCALCSIZE` keeps the client area the whole window, and any frame styles Windows adds back are removed. `0027-relay-agent-token.patch` = the engine proves to the launcher's agent that it is the engine the launcher started: the launcher passes a random `GEN_RELAY_TOKEN` and every engine socket (the two game sockets and the checksum reporter's) sends `Packet::Auth` first; the agent ignores any other local address, so another process (or user) on the machine can no longer bind the game ports to eavesdrop or inject packets. `0028-logic-height-map-clip.patch` = beta.6 logs (Windows host, macOS client) showed every input of the terrain-aligned transforms equal except the terrain height of 436 objects (Mac 18.125, Windows 25.0): `BaseHeightMapRenderObjClass::getHeightMapHeight` took its off-map branch through `getClipHeight()`, which reads `m_map` (the client's copy, whose size follows the screen under patch 0001) instead of the logic height map the rest of the function uses; it now clamps into the logic map. (The sync log keeps only the last 64000 lines of a frame, so frame 0 starts mid-way; compare aligned from the end.) `0029-borderless-patch-builds-on-macos.patch` = 0026's `WM_NCCALCSIZE/WM_NCPAINT/WM_NCACTIVATE` cases do not exist in the macOS Win32 shim, which broke the macOS engine build of v0.3.0; they are now under `#ifdef WM_NCCALCSIZE`. Engine patches are only compiled by the release workflow's dry run (Actions > Release > Run workflow on the branch): run it on every PR that touches `patches/`. `0030-height-map-sync-log.patch` = after 0028 the beta/0.3.1 logs (Windows host, macOS client, map `Unity B ZH v2`) still differed only in `terrainAtPos` for 436 `alignOnTerrain` calls with angle 0 and a straight-up normal (Mac 18.125 = height byte 29, Windows 25.0 = byte 40), which sets the Z of the 33 objects whose transform CRC differs; 0028 changed neither value. This adds, to the sync log only, a fingerprint of the logic height map (extent, border, FNV hash of all heights, whether it is the client's map) and the inputs of the first six off-map lookups (`addCRCDebugLineNoCounter`, because client code calls the same function). `0030`/`0032` log a fingerprint of the logic height map, the first off-map lookups and the first terrain-sticking placements (`[sync-hm]` lines on stderr, so in `engine.log`: the sync log only keeps the last 64000 lines of a frame). `0031-player-name-saves-on-macos.patch` = `UnicodeStringToQuotedPrintable` walked the string two bytes at a time and stopped at two zero bytes, which is the end of the string only where `wchar_t` is 16 bits; on macOS (32-bit) a player name was saved as its first letter, so the LAN lobby always showed `M`. It now writes/reads 16-bit units whatever the size. The launcher also passes `GEN_PLAYER_NAME` (Online page; this computer's name until set) and `LANPreferences::getUserName` prefers it. `0033-crc-interval-after-sync-window.patch` = sync logs run with `-NetCRCInterval 10`; after frame 300 the multiplayer checksum interval goes back to 100 (a pass over every object ten times as often was felt as stutter). `0034`-`0040` are upstream fixes from TheSuperHackers/GeneralsGameCode (the engine base is upstream of 2026-05-15; see `docs/upstream-fixes.md` for what was taken and what conflicts), each patch headed by the upstream commit. `0041-simulation-id-4.patch` raises `kRallypointSimulationId` to 4 because 0035/0036 change when the logic random numbers are drawn. `0042-crc-interval-only-in-multiplayer.patch` = 0033 read `TheGameInfo->getCRCInterval()` before checking that a multiplayer game was running, so the game crashed at start (the menu's background scene runs `GameLogic::update` with no game info; null + 0xc) in 0.3.3 on macOS and Windows; the interval is now only read in a multiplayer game or replay. A new engine patch that touches game logic needs a menu start and a skirmish start checked before release. Check a build really has the writer with `strings -a generalszh | grep DebugFrame_`. These need a real macOS test. All build in CI on macOS and Windows; none has been played in a real game.
- `tests/` - `sh tests/run.sh` applies patches and runs the standalone engine-math tests (plain `c++`, no engine build); `relaywire_test` checks the same golden bytes as the Rust protocol tests.
- `launcher/core/` - GUI-free Rust crate, all logic and tests: `steam.rs` (find installs by `.big` files), `assets.rs` (Steam download with DepotDownloader: native on every OS, so no Rosetta; pinned version + SHA-256 per platform, checksums from `.github/workflows/tool-checksums.yml`; password goes to its stdin when it prompts, never argv; prompts have no trailing newline and a "wrong code" notice can arrive before or after the next prompt because stdout/stderr are separate pipes; `-remember-password` makes later runs prompt-free; phone approval (push notification) is the default sign-in, so `-no-mobile` is only added when the user taps "Enter a code instead" (the interrupted run is restarted, reusing the in-memory password), and a quiet 6 s of signing in also shows the phone hint because the tool's exact wording is unverified; tested against a fake tool), `extract.rs` (safe unzip/7z/rar/tar/installer-exe via system tools: lists and checks entries for `..`/absolute paths before extracting, rejects symlinks), `mapview.rs` (the map viewer: the preview `.tga` of a map folder is decoded (uncompressed or run-length, 24 or 32 bit) and sent to the page as base64 RGBA for a canvas; the `.map` is unpacked (`EAR\0` = EA RefPack, `ZL5\0` = zlib, or plain `CkMp`, with size limits) and its chunks read for the playable size (`HeightMapData` minus the border, ten units per cell) and the `Player_N_Start` waypoints in `ObjectsList`, returned as fractions of the playable area with y up. Checked against all 36 maps of a real install and 777 of the Epic Showdown pack; the 22 without start positions there are solo missions), `maporg.rs` (the map organiser: maps switched off are moved to `<app data>/GeneralsZH/MapLibrary/disabled`, `library.json` remembers each map's pack, nothing is deleted unless asked; big packs (`start_disabled`) are added switched off, and a pack whose site blocks automated downloads (`manual`, such as Epic Showdown 707 from ModDB) is fetched by the player and chosen as a file), `maps.rs` (map packs: download a zip with curl, safe-extract, copy only the map folders (a folder holding a `.map`) into `<Documents>/Command and Conquer Generals Zero Hour Data/Maps`; catalog `mods/mappacks.json` lists GenTool's `Maps_*_ZH.zip` files, URLs verified with HEAD requests), `selfupdate.rs` (applies a downloaded update: macOS mounts the dmg, copies and `codesign --verify`s the app, then a detached sh script waits for our PID, swaps the bundle (rolls back on failure) and reopens; Windows runs the NSIS setup with `/S` from a hidden PowerShell script (`CREATE_NO_WINDOW`, not `DETACHED_PROCESS`: that flag makes PowerShell exit before the script runs, so the app closed and never came back; the script logs the installer result and still restarts the previous app if the installer fails) then restarts the exe. Release notes are kept whole (they used to be cut at 1,500 characters) and the What's new screen renders headings, lists and bold, in a dialog that scrolls. It falls back to opening the installer when the app folder is not writable. `whats-new.json` marker shows the notes once if its version equals the running one), `update.rs` (GitHub releases updater: semver precedence incl. prereleases, per-OS installer pick, SHA256SUMS check, only this repo's download URLs; CI stamps the tag into the binary with `RALLYPOINT_VERSION`), `proc.rs` (`quiet()`: CREATE_NO_WINDOW for every helper process on Windows; the launcher itself uses the GUI subsystem in release builds), `clickteam.rs` (Clickteam Install Creator overlay `wwgT)H`: Shockwave's installer. Writes `.big`/`.gib` and other data, drops `.exe`/`.dll`/shortcuts so the mod's Windows launcher is never started; deflate via `flate2`, bzip2 via `bzip2`), `icons.rs` (setup downloads GenTool Control Bar HD on its own, pinned URL + SHA-256, and loads it as a mod layer), `mods.rs` (catalog with `addon_for` add-ons: the engine loads one mod folder, so `stack()` hard-links the selected layers into `Mods/.run`, inserting each add-on's base first; `compose()` remains for a single pair; install from archive/folder/exe, including Clickteam, into `Mods/<folder>`, flatten wrapper dirs, require `.big` files, remove, Downloads-folder watcher), `engine.rs`, `graphics.rs` (Settings camera height and an optional high-quality Options.ini merge), `diagnose.rs` (game files, the base game, and the engine crash report), `launch.rs` (`GEN_ZH_PATH`, optional raised camera, and the engine log), `config.rs` (`<app data>/GeneralsZH/config.json`, 0600), `agent.rs` (tunnel agent).
- `launcher/src-tauri/` - thin Tauri 2 shell exposing core as commands (mod installs are `async` + `spawn_blocking` so the window doesn't freeze). `launcher/ui/` is plain HTML/CSS/JS built from small DOM components in `app.js` (`h()` helper, no `innerHTML`, no inline styles because of the CSP): sidebar pages Play/Mods/Online/Settings plus the first-run wizard (`config.setup_done`). `scripts/ui-preview/` renders it in a normal browser with a mocked backend (`python3 -m http.server`, open `scripts/ui-preview/index.html#fresh`); check changes there, including `null` text from `replaceChildren` (use `fill()`).
- `mods/mods.json` - mod manifest. A mod is a folder under `<app data>/GeneralsZH/Mods/` loaded with `-mod`.
- `shared/` (`generals-proto`) - UDP wire protocol and `room_verifier`. `server/` (`rallypoint-server`, Linux) - `Server` state machine in `lib.rs` (no sockets or clocks; all tests there), `geo.rs` (country filter), `main.rs` (env config, CLI, UDP loop).
- `Makefile`, `.env.example`, `docker-compose.yml`, `server/Dockerfile` - running the server. CI smoke-tests the container with `launcher/core/examples/agent_cli.rs` (a full encrypted sign-up and join using the real agent).
- `.github/workflows/ci.yml` - fast tests only, on push/PR. `release.yml` - engine + launcher bundles + server image, only on `v*` tags or manual run (manual never publishes). The Windows engine ships with the x86 `msvcp140.dll`, `msvcp140_atomic_wait.dll` and `vcruntime140.dll` it was built against: an older system copy (14.29) crashes in `std::mutex::lock` a few seconds after start.

## Server design
- Encryption (`shared/src/secure.rs`, the `snow` crate, Noise `NK` over X25519/ChaCha20-Poly1305/SHA-256; no hand-rolled crypto): the server has a long-term key pair (`serials.key` next to the serials, 0600; `rallypoint-server key` prints the fingerprint). A client learns it once with `KeyRequest`/`KeyReply` (padded so the reply is smaller than the request), saves it per server in the launcher config (`server_keys`, trust on first use) and from then on only that server can complete a join; a different one is reported as `ServerKeyChanged` and refused until the player chooses `relay_forget_key`. Handshake: `Hs1{cookie, msg1}` where msg1 is the client's `Register` or `Hello{serial, room, verifier}` encrypted to the server key (an unknown cookie only gets a small `Challenge`: no key exchange is spent on spoofed senders), answered by `Hs2{msg2}` carrying `Issued`/`Welcome{vip}`/`Reject`. The server's cookie is mixed into the Noise handshake as its prologue (`client_start`/`server_accept` take it), so a recorded first message only opens from the address whose cookie it was made with: replaying a captured `Hello` or `Register` from elsewhere cannot lock a player out (`InUse`) or use up sign-ups. The agent sends a throw-away first message to get the cookie, then builds the real one. After that every datagram is `Transport{counter || AEAD(packet)}` with per-direction keys and a 64-packet replay window; forged, replayed or unknown-session datagrams get no reply. A retransmitted msg1 is answered from a cache (same reply, no second session). `Wire` is the outer layer, `Packet` the content (also what the engine speaks to the local agent, unchanged).
- Serials are identities issued automatically and kept out of the UI. The challenge cookie (HMAC-like SHA-256 over a server secret + source IP + minute) stops spoofed sign-ups; the Challenge is no bigger than the request (no reflection). 5 sign-ups per IP per hour. `GENERALS_REGISTRATION=closed` makes the server admin-issue only (`rallypoint-server issue <label>`).
- A serial that joins again (new address after a network change, or a stale session) takes over its old session instead of being refused `InUse`, and a returning player gets the same virtual address back (`room_vips`): a lobby went stale because the agent was locked out for the 30 s the server needs to forget a dead session, or came back with a different address than the running game was started with. The agent rejoins after 8 s of silence and shows what it is waiting for (`Agent::connection`). The relay logs a `traffic:` line a minute and any datagram slower than 5 ms. The container runs on the host network (no NAT or userland proxy in the path).
- Rooms: created by the first `Hello` for a name with its `verifier` (iterated SHA-256 of room+password, so the password never travels or is stored), removed when empty (explicit `Leave`, timeout 30 s, serial revoked). Max 256 rooms x 8 players; 10 wrong passwords per IP per 10 minutes. Broadcast/unicast never cross rooms; each room has its own `10.77.0.x` space.
- Country limit: `ALLOWED_COUNTRIES` + zone files in `GEO_DIR` (`make geo` downloads ipdeny.com aggregated lists). Fails closed (listed country without a file allows nobody); private ranges pass only with `ALLOW_PRIVATE=true` (default false: Docker's userland proxy makes IPv6 clients look like its 172.x gateway). IPv4-mapped IPv6 sources are judged by their IPv4 address, other IPv6 is refused. Blocked sources get no reply.
- Game only: the relay carries nothing but the engine's own datagrams. Logical ports are limited to 8086 (lobby; broadcast is lobby-only) and 8088 (game), payload ≤ 1100 bytes, and `generals_proto::is_game_packet` checks the engine's obfuscation, CRC and magic 0xF00D (verified against packets built by the engine's own `Transport` code; `game_packet` builds one for tests). The agent applies the same filter in both directions and ignores `Bind` for other ports.
- Abuse limits: per-session 600 packets and 400 kB per second (dropped, not echoed); per address (IPv6 by /64) 16 sessions, 20 unknown-serial guesses and 10 wrong passwords per 10 minutes, 5 sign-ups an hour; 300 sign-ups an hour server-wide. Housekeeping (expiry, serial file reload) runs once a second in `main.rs`, never per datagram.
- Diagnostics: a signed `StatsRequest` is answered with `Stats` (counts only: rooms, players, players in your room, load %, packets/s and kbit/s of the last second, uptime, version; never other rooms' names). The agent pings every 2 s, keeps 30 results for latency, jitter and loss (`Health`), and the Online page shows them (`relay_diagnostics`).
- Limits: the first visit to a server trusts whoever answers `KeyRequest` (like SSH); pinned afterwards. msg1's payload (serial, room proof) has no forward secrecy if the server key leaks later (Noise NK); everything after has. The agent's loopback socket only listens to local addresses that sent the engine token (`Packet::Auth`, see patch 0026), and only game packets pass it; an unsigned `KeyReply`/`Challenge` is ignored once a session exists, so a forged one cannot drop a connected player. A serial is stored per server (`Config::serials`) and only sent to the server that issued it (a legacy single serial is kept only for a server whose key was saved). Extraction lists archives and refuses links before writing anything (`extract::find_link`), Clickteam blocks are decoded through `copy_limited` (size from the header is never allocated up front, 12 GB total cap).

## Rules
- **Pull requests only.** Never push to `main`. Branch (`feat/…`, `fix/…`, `docs/…`), push the branch, open a PR with `gh pr create`, let CI run, and merge after review. Release tags are the one thing pushed directly, and only from a merged `main` (`make release VERSION=…`).
- Licensing: launcher/server/shared/scripts/docs are MIT (`LICENSE`). Anything derived from the engine (`patches/`, `RelayWire.h`, other engine edits) is GPL-3.0 + EA terms. Never copy engine code into the MIT parts, and keep the launcher talking to the engine only as a separate process.
- Put logic in `launcher/core` or `server` lib with a test; keep the Tauri shell and UI thin.
- Detect games by `.big` files (`INIZH.big` = Zero Hour, `INI.big` = Generals). Steam app IDs (Generals 2229870, Zero Hour 2732960) are used only by the steamcmd download.
- A room password is stored only when the player ticks "Remember the password" for a saved server: in `config.json` (0600, `Config::room_passwords`), never logged, never returned to the page (it only learns that one is saved). The Steam password is never stored.
- Never redistribute EA assets, Miles or Bink. The user's own Steam copy supplies game data. Never store or log the Steam password; it only goes into the short-lived 0600 sign-in script (never argv), and logs are scrubbed of it.
- Mod catalog entries need verified official URLs (ModDB blocks automated fetches with 403, so open the page in a browser to check); never invent one, and never scrape direct download links: the launcher opens the official page and watches Downloads instead.
- UI: no `innerHTML` with backend data (folder names are attacker-controlled).
- Server loop must never die on I/O errors (no `?` inside `run`'s loop).
- No new dependencies when std or serde does it (sha2 is the exception: don't hand-roll crypto).

## Roadmap
1. Verified in a real game: widescreen/HiDPI (0001), Steam download with a real account, two-machine play through the relay (a Mac and a Windows PC played a game through it on 2026-10-26, with a harmless-looking checksum difference at frame 0 in ~33 static objects' stored height; the sync logs match frame for frame otherwise). Still to verify: Windows engine data lookup (cwd vs registry) and longer games.
2. Linux engine; more catalog mods (needs verified pages); loose-file mods (no `.big`).
   (was 2) GeneralsX (https://github.com/fbraz3/GeneralsX) already targets Linux x86_64 (DXVK/Vulkan, SDL3, OpenAL) from the same TheSuperHackers base; the likely route is basing the Linux build on it rather than porting our own renderer. It publishes no discrete fix list, so cherry-picking means reading its commit history for the specific area (macOS/net/rendering fixes) and porting by hand.
3. Determinism (macOS arm64 vs Windows x86 desync): `-ffp-contract=off`, deterministic trig, RNG audit; headless engine on the server as a per-frame CRC referee.
4. Gameplay features, all engine work in a lockstep game, none started:
   - Save/load multiplayer: needs the save to be written identically on every client and a "load" handshake that restores all clients to the same frame (the game's save format is not network-aware).
   - Controlling allied units: command validation (`Player`/`Object` ownership checks in command processing) needs an "allowed controller" relation that is identical on every client; AI-owned allies and shared vision/economy rules need decisions.
   - Co-op / shared player: several humans issuing commands for one `Player` slot; commands from different clients for the same player must be ordered deterministically (the net layer already orders commands per frame), and the lobby needs a shared slot concept. Related to the item above.
5. Mod downloads inside the launcher; the relay as a public server list.
